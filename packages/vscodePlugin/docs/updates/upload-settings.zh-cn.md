# Cherry Markdown：上传配置重要更新

**PicGo 继续支持，原有 binary 上传保持不变。** 本次调整的是配置读取规则，不会自动迁移、修改或删除你的设置。

## 哪些情况需要处理？

| 变化                                                    | 你需要注意的事项                                   |
| ------------------------------------------------------- | -------------------------------------------------- |
| 旧 `UploadType`、`PicGoServer` 和旧上传模式枚举不再读取 | 按下面的现行配置重新设置                           |
| 文件夹级配置开始生效                                    | 多根工作区上传前，检查预览底部的目标和配置来源     |
| 上传器整体取自同一层设置                                | 项目地址不再继承用户级认证头，请补齐该层需要的配置 |
| 无效模式、地址、字段名或资源目录直接报错                | 修正配置后再上传，不会自动切换目标或协议           |
| 旧 `Theme` 不再读取或迁移                               | 使用现行主题设置；已保存的手动主题保持有效         |

受限模式仍允许用户级上传配置，项目配置需通过 VS Code 原生工作区信任界面授权。不要把认证信息提交到项目仓库。

## PicGo 用户如何配置？

在 PicGo 2.4.0+ 中配置好图床并启用 HTTP 服务，然后在 VS Code 设置中手动填写（地址按实际修改）：

```json
{
  "cherryMarkdown.ImageUploadMode": "remote",
  "cherryMarkdown.CustomUploader": {
    "enable": true,
    "url": "http://127.0.0.1:36677/upload",
    "format": "multipart",
    "fieldName": "files",
    "headers": {}
  }
}
```

插件发送文件内容，自动生成表单边界和长度。需要密钥时，在 `headers` 中添加 `Authorization`。Remote SSH、容器或 WSL 中的 `127.0.0.1` 指扩展宿主所在环境，请确保地址可达。

已有二进制 HTTP 上传器可保持原配置：省略 `format` 时仍使用 `binary`。服务端失败不会触发自动协议回退。

## 这条通知还会出现吗？

本条重要变更通知在当前 VS Code 配置档中只自动提示一次，关闭也算已读；普通 patch 或重载窗口不会再次提示。此功能首次上线无法可靠区分新装与升级，因此首次启用都会提示一次。

通知记录只保存在扩展内部状态，不修改用户设置。上传时的配置错误提醒继续保留。以后可从命令面板运行 **Cherry Markdown：查看更新说明** 再次打开本页。
